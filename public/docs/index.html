Words in Life 把生活場景變成英文單字卡。這份文件帶你從使用者操作，走到辨識、學習規則與瀏覽器裡的資料。

探索架構在本機啟動
繁體中文 · 可互動探索 · 單一 HTML，無外部依賴

它做了哪些事？

拍攝、理解、收藏，再回來複習。主要功能串成一個學習循環。

  • 拍照與辨識

    首頁開啟後置相機，也能選取圖片。實際照片透過 Gemini 取得場景、英文單字、中文、音標、例句與物件位置，再產生方形照片裁切。

  • 單字收藏

    從辨識結果收藏單字，以照片格狀或列表瀏覽。支援中英文搜尋、分類篩選、單字詳情、原圖與瀏覽器語音發音。

  • 翻卡複習

    先看物件照片回想單字，再翻面查看答案。每次回答記錄複習次數、記住次數、最近複習時間與記住比例。

  • 每日尋寶

    開啟任務時，AI 參考生活常見物件、時節與單字簿，安排一項複習與兩項新探索；空收藏時產生三項新探索。當日結果固定保存，缺 key 或生成失敗時使用本機備援題庫。三項全數完成才計入連續完成天數。

  • 範例與設定

    四組生活範例可直接體驗。設定頁讓使用者儲存或清除 Gemini API key；沒有 key 時仍可使用範例。

    AI 怎麼選出今天的任務？

    生成時只提供本機日期、月份、時區、最多 500 個已知單字名稱與 30 個複習候選摘要。候選優先考量尚未複習、記住比例偏低與久未複習；每項輸出包含提示、別名、分類與選題理由。任務文字請求不含照片。

    System prompt 要求選擇容易拍攝的生活物件，適度參考時節，但不把時區當作所在地或天氣證據。新字不得與單字簿重複，別名只能指同一物件，例如 cup 不接受 coffee。程式驗證數量、格式、目標／別名不重疊及複習／新字比例；物件可取得性與別名語意仍取決於模型品質。

    當日首次生成後固定保存；開始或完成任務後也不會更換目標。缺 key、無效回應或服務失敗會固定使用當日備援；當天補上 key 不會重抽。實際提示位於 src/repository/gemini/missionRequest.ts。

    單字與照片，分開保存。

    IndexedDB 資料庫 words-in-life-storage 使用六個 object store。一般快照只讀單字、學習狀態與版本；圖片顯示時才讀取 Blob。

    IndexedDB 儲存區與用途
    儲存區內容與用途
    words單字、例句、照片參照、收藏時間，以及各單字的複習統計。
    learning目前日期、三個任務、完成狀態、連續完成天數與最後完成日期；generation 保存生成權、AI／備援來源與固定狀態。
    photos以內容雜湊識別的照片 Blob，讓相同內容共用儲存。
    photoMetadata照片 MIME type、大小與引用次數。最後一個資料引用移除時刪除 Blob。
    operationscommandId 對應的操作結果與版本，避免同一操作重複套用。
    meta全域 revision 與 initialized，供原子交易檢查版本與初始化狀態。

    照片怎麼找到？

    PhotoRef 分成靜態資源路徑與已儲存照片 ID。已儲存照片使用 photo:SHA-256 作為內容 ID；元件經 URL 管理器取得共用 Blob URL，最後一個使用者釋放後回收 URL。刪除資料引用與釋放畫面 URL 是兩件事。

    多個分頁怎麼同步？

    每次提交都在交易內核對 expectedRevision。衝突時重新讀取、重算與提交，最多三次；成功後以 BroadcastChannel 通知其他分頁，頁面回到前景時也重新載入。

    本機設定與資料界線Words in Life 的資料庫與設定儲存鍵統一使用 words-in-life 命名空間，不讀取或遷移舊名稱的資料與設定。API key 存在 localStorage 的 words-in-life-gemini-key-v1；相機開關使用 words-in-life-camera-enabled-v1。儲存 key 不會驗證其有效性；實際辨識時照片與 key 會直接送往 Google，任務生成則傳送日期、時區與單字／複習摘要。專案目前沒有登入、雲端同步或資料匯入匯出功能。
    初始資料與舊版資料

    新資料庫首次初始化加入四個既有範例單字；刪空後重新載入仍保持空白。目前不讀取、遷移或清除舊名稱的資料庫與 localStorage；收藏、API key 與相機偏好皆使用新命名空間。

    常用驗證指令

    • 型別、核心測試與正式建置

      check 依序執行 lint、test 與 build；核心測試不需相機或 Gemini key。

      npm run check
    • 瀏覽器流程

      先安裝 Playwright Chromium，再執行 E2E；測試會啟動獨立伺服器與瀏覽器情境。

      npx playwright install chromium
      npm run test:e2e
    • 正式輸出與本機預覽

      build 產生 dist/，包含本份文件；執行 preview 後使用終端顯示的網址檢查正式輸出。

      npm run build
      npm run preview
    部署與測試範圍靜態主機部署 dist/，並為設計系統路由設定回退至 index.html。相機需要 HTTPS 或 localhost。模擬 Gemini 與相機測試涵蓋程式流程；實際模型可用性、相機硬體與語音仍需在目標環境驗證。
