# Reliability fixes and feature boundaries

The existing review and follow-up authorize a gradual refactor, preserving the static frontend and existing camera, collection and quiz flows.

## Decisions
- Keep React state and hooks; no new global state framework or backend.
- Persist one versioned library snapshot (words, daily mission state) and content-addressed photo Blobs in IndexedDB. Commit metadata and images atomically. Publish UI changes only after successful persistence. Keep legacy localStorage data until migration succeeds; validate at both read boundaries.
- Keep API credentials separate in the existing settings store.
- Use application-owned normalized word identifiers, independent of model IDs.
- Share pure mission matching, date rollover and streak rules between samples and live recognition. A day counts after all three missions; initial streak is zero and a gap resets it. Complete at most one mission per analysis, preserving current behavior.
- Give recognition one discriminated state, a request generation and cancellation controller. A failed request always retains its own source photo. Print animation is a bounded presentation wait.
- Persist per-word review counts, remembered counts, last review and mastery percentage. This is a review history summary, not a spaced-repetition algorithm.
- Retain design tokens and visuals; move existing CSS into explicit base/composition layers instead of implicit import-order overrides.

## Sequence and verification
1. Boundary validators and mission rules, with Node unit tests.
2. Transactional repository and legacy migration; browser tests for persistence, shared photo storage and write failures.
3. Collection, missions and recognition hooks; compose in App.
4. Persist review results, add error recovery, organize styles and standardize test commands.
5. Type checking, production build and all existing browser scripts plus targeted regression scenarios. Use fake camera and intercepted Gemini; do not claim physical camera or live provider verification.

## Alternatives considered
Keeping images in localStorage leaves quota and synchronous serialization problems. A backend would add account/deployment scope that this local-first app does not need. IndexedDB plus small feature hooks addresses the observed failures with the existing deployment model.

## Completed validation
- `npm run check`: strict TypeScript, 9 domain tests and production build passed.
- `npm run test:e2e`: all 6 browser scripts passed using installed Chrome, including the runner's automatic server startup and shutdown.
- The catalog and six preview routes loaded without page errors; mobile home and collection screenshots were inspected.
- Midnight regression exposed stale selected mission objects. Camera targets, missed-task hints, celebration and photo-viewer selections now resolve against the current daily mission list, rather than relying on a later effect to clear expired objects.
- Live Gemini, physical camera and speech services remain outside the mocked test coverage.
